# زیرساخت و پنل مدیریت عملیاتی دیزاینستون — فازهای اول تا سوم

گالری استاتیک فعلی بدون تغییر باقی می‌ماند. این شاخه Backend مستقل PHP/PDO/MySQL، API عمومی و پنل فارسی امن را اضافه می‌کند. HTML، JavaScript، CSS و تصاویر اصلی سایت تغییر نکرده‌اند و سایت هنوز به API متصل نیست.

## رفتار نهایی

- ورود و خروج با همان امنیت فاز دوم؛ فقط یک مدیر با ساخت اولیه CLI و بدون رمز پیش‌فرض.
- افزودن و ویرایش نمونه‌کار، دسته و ترتیب، انتشار/لغو انتشار و بایگانی با تأیید؛ بازیابی همیشه منتشرنشده است.
- مدیریت دسته‌ها با slug ثابت و جلوگیری از حذف دسته دارای نمونه‌کار، حتی بایگانی‌شده.
- آپلود واقعی JPEG/PNG/WebP تا ۱۰ مگابایت با اعتبارسنجی MIME/ابعاد، بازرمزگذاری و نام تصادفی؛ پیش‌نمایش محلی قبل از ارسال.
- فایل‌ها بیرون public هستند؛ media.php فقط تصاویر محتوای عمومی مجاز را سرو می‌کند. فایل قبلی در تعویض تصویر حذف نمی‌شود و خطای ذخیره فایل تازه را پاک می‌کند.
- تماس با اعتبارسنجی و ذخیره تراکنشی؛ API عمومی فقط تنظیمات تماس مجاز را برمی‌گرداند.
- Seed تکراری و بدون بازنویسی، هفت دسته و ۲۲ نمونه‌کار اولیه را حفظ می‌کند و بایگانی را دوباره منتشر نمی‌کند.

## استقرار

روی دیتابیس موجود فاز دوم migration یک‌باره 003 لازم است؛ روی فاز اول ابتدا 002 و بعد 003 اجرا شود. نصب تازه فقط schema به‌روز می‌خواهد. GD و Fileinfo و PDO MySQL، مجوزهای محدود نوشتن و storage/uploads قابل‌نوشتن لازم‌اند. ریشه عمومی فقط backend/public و HTTPS عملیاتی الزامی است. راهنمای ویندوز و محدودیت‌های PHP در CONTENT.md و راهنمای حساب در ADMIN.md آمده‌اند.

Backend از ساخت استاندارد Jekyll برای Pages حذف شده است؛ در انتشار سفارشی، artifact باید فقط فایل‌های عمومی سایت را شامل شود. اتصال گالری اصلی به API و نگاشت origin تصاویر قدیم/جدید متعلق به فاز چهارم است.

## اعتبارسنجی

روی PHP 8.4 / MySQL 8.4 / GD: تست‌های فاز اول و احراز هویت، افزودن/ویرایش واقعی با multipart، هر سه نوع تصویر، رد فایل بیش از سقف و PHP تغییرنام‌یافته و تصویر خراب، رد ابعاد نامعتبر، پاک‌سازی payload اضافی، شکست واقعی SQL و پاک‌سازی فایل، بایگانی/بازیابی و Seed، دسته وابسته، تماس و خروجی API موفق بودند. migration روی ساختار 6436647 با حفظ ۲۲ نمونه‌کار و هفت دسته اجرا شد. Chromium پیش‌نمایش پیش از ارسال، ثبت، بایگانی/بازیابی، شماره فارسی و نمایش دسکتاپ/موبایل را تأیید کرد.

ویندوز، استقرار واقعی HTTPS/Pages و encoder جایگزین بدون WebP در این محیط آزمایش نشده‌اند. تراکنش فایل‌سیستم و MySQL مشترک نیست؛ در قطع ناگهانی فرایند ممکن است فایل بی‌مرجع باقی بماند. ابزار audit فقط گزارش می‌دهد و هیچ رسانه‌ای خودکار حذف نمی‌شود.

هیچ ادغامی بدون تأیید مالک انجام نشود.
