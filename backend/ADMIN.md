# پنل مدیریت — احراز هویت و اجرای محلی

این مرحله هیچ فایل عمومی سایت یا تصویر را تغییر نمی‌دهد. سایت همچنان داده استاتیک قبلی را می‌خواند. API عمومی فاز اول نیز مستقل و بدون تغییر قرارداد باقی است. مدیریت واقعی نمونه‌کار، دسته، آپلود و تماس در فاز سوم فعال شده است؛ migration و راهنمای آن در [CONTENT.md](CONTENT.md) آمده است. ثبت‌نام عمومی وجود ندارد.

## دیتابیس موجود از فاز اول

ابتدا از دیتابیس نسخه پشتیبان بگیرید. با حساب مجاز تغییر ساختار وارد MySQL شوید و دیتابیس را انتخاب کنید:

```powershell
mysql -u root -p designestoon_db
```

داخل MySQL و با مسیر واقعی مخزن:

```sql
SOURCE C:/projects/desinestoon/backend/database/migrations/002_admin_security.sql;
EXIT;
```

این migration فقط یک بار اجرا می‌شود. اگر ستون singleton یا جدول admin_login_limits از قبل وجود دارد، آن را دوباره اجرا نکنید. برای نصب تازه از schema.sql به‌روز استفاده کنید و migration را جدا اجرا نکنید. اجرای مجدد schema روی دیتابیس قدیمی جای migration را نمی‌گیرد. اگر بیش از یک مدیر وجود داشته باشد، قید یکتا اضافه نمی‌شود؛ migration هیچ حسابی را حذف نمی‌کند. در این حالت پیش از ادامه، حساب‌ها باید با تصمیم مالک بررسی شوند. دستورات DDL در MySQL تراکنشی نیستند؛ قبل از تلاش مجدد وضعیت ستون و جدول را بررسی کنید.

قید یکتای ستون تولیدشده ثابت `admins.singleton` اجازه بیش از یک حساب را حتی با نام کاربری متفاوت نمی‌دهد. جدول جدید `admin_login_limits` تنها یک ردیف شمارنده دارد. جدول‌های categories، projects، media و settings و داده‌های آن‌ها تغییر نمی‌کنند.

## مجوزها

برای ساخت حساب اولیه، حساب CLI به SELECT و INSERT روی admins نیاز دارد. این مجوز INSERT را به حساب وب ندهید. مجوزهای زیر مربوط به احراز هویت و خواندن هستند؛ برای نوشتن محتوای فاز سوم، مجوزهای تکمیلی CONTENT.md هم لازم‌اند:

```sql
GRANT SELECT ON designestoon_db.admins TO 'designestoon_app'@'127.0.0.1';
GRANT SELECT ON designestoon_db.categories TO 'designestoon_app'@'127.0.0.1';
GRANT SELECT ON designestoon_db.projects TO 'designestoon_app'@'127.0.0.1';
GRANT SELECT ON designestoon_db.media TO 'designestoon_app'@'127.0.0.1';
GRANT SELECT ON designestoon_db.settings TO 'designestoon_app'@'127.0.0.1';
GRANT SELECT, UPDATE ON designestoon_db.admin_login_limits TO 'designestoon_app'@'127.0.0.1';
```

مجوزهای گسترده باقیمانده از توسعه فاز اول را بازبینی و حذف کنید؛ GRANT محدود به‌تنهایی مجوز گسترده قبلی را لغو نمی‌کند. حساب جداگانه فقط‌خواندنی برای API عمومی همچنان توصیه می‌شود؛ در استقرار تفکیک‌شده، هر فرایند می‌تواند متغیرهای اتصال خودش را داشته باشد. `.env` را هرگز داخل public یا Git قرار ندهید.

## ساخت تنها حساب مدیر در ویندوز

پیش‌نیازها مطابق README: PHP 8.2+ و PDO MySQL، MySQL 8.0.16+، schema/migration اعمال‌شده و backend/.env تنظیم‌شده. مسیر PHP در PATH باشد.

برای فرمان CLI می‌توانید DB_USER و DB_PASSWORD را موقتاً از حساب دارای مجوز SELECT/INSERT مدیران تأمین کنید. نام کاربری انتخابی ۳ تا ۱۰۰ نویسه لاتین، عدد، نقطه، خط تیره یا زیرخط است. اسکریپت PowerShell رمز را دو بار با ورودی مخفی دریافت می‌کند:

```powershell
# فقط برای ساخت حساب اولیه؛ تنظیمات وب بعد از فرمان بازیابی می‌شوند.
$previousUser = $env:DB_USER
$previousPassword = $env:DB_PASSWORD
$dbSecret = Read-Host 'رمز حساب دیتابیس دارای مجوز ساخت مدیر' -AsSecureString
try {
    $env:DB_USER = 'root' # یا حساب CLI محدود با مجوز SELECT/INSERT روی admins
    $env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $dbSecret).Password
    & ./backend/scripts/create-admin.ps1 -Username adminname
} finally {
    $env:DB_USER = $previousUser
    $env:DB_PASSWORD = $previousPassword
    $dbSecret.Dispose()
}
```

اگر PowerShell اجرای اسکریپت محلی را محدود کرده است، طبق سیاست سیستم خود از ترمینال مجاز استفاده کنید؛ سیاست امنیتی سراسری را غیرفعال نکنید. رمز حداقل ۱۲ نویسه، حداکثر ۷۲ بایت و بدون خط جدید است. محدودیت بایت برای جلوگیری از کوتاه‌شدن بی‌صدای رمز در bcrypt است. هش با `password_hash(PASSWORD_DEFAULT)` ساخته می‌شود. رمز نه در آرگومان‌ها و نه در فایل ذخیره می‌شود؛ به‌صورت کوتاه‌مدت در حافظه فرایند و لوله استاندارد وجود دارد. از transcript یا ابزار ثبت ورودی محرمانه استفاده نکنید.

در لینوکس/مک، ترمینال تعاملی ورودی را مخفی می‌کند:

```sh
php backend/scripts/create-admin.php adminname
```

گزینه `--password-stdin` برای لوله امن محلی و تست وجود دارد؛ رمز واقعی را با echo، آرگومان خط فرمان یا فایل موقت ارسال نکنید. فرمان در صورت وجود هر مدیر، بدون تغییر رمز یا ساخت حساب دوم شکست می‌خورد. بازیابی/تغییر رمز هنوز رابط ندارد و به فاز بعد موکول شده است.

## اجرای پنل در ویندوز

با تنظیمات حساب وب در backend/.env، از ریشه مخزن:

```powershell
php -d upload_max_filesize=10M -d post_max_size=12M -d memory_limit=256M -d display_errors=0 -S 127.0.0.1:8080 -t backend/public
```

در مرورگر مسیر `/admin/login.php` همین سرویس را باز کنید. پنل در `/admin/`، نمونه‌کارها در `/admin/projects.php`، دسته‌ها در `/admin/categories.php` و تماس در `/admin/contact.php` هستند. خروج فقط با POST و CSRF معتبر انجام می‌شود.

سرور داخلی PHP فقط برای توسعه محلی است. در هاست، document root باید backend/public باشد و HTTPS اجباری است. HTTPS باید در متغیر معتبر HTTPS وب‌سرور منعکس شود؛ کد به X-Forwarded-Proto ارسالی کاربر اعتماد نمی‌کند. در reverse proxy فقط پراکسی مورد اعتماد باید HTTPS را تنظیم کند و اتصال مستقیم به upstream مسدود باشد. استثنای HTTP صرفاً برای REMOTE_ADDR لوپ‌بک توسعه است؛ در استقرار پشت پراکسی محلی، الزام TLS را در پراکسی نیز enforce کنید. مسیرهای کد، SQL، تنظیمات و storage خارج از document root باقی می‌مانند. پردازش استاندارد Pages همچنان backend را حذف می‌کند؛ در artifact سفارشی فقط فایل‌های استاتیک اصلی سایت قرار بگیرند.

## امنیت و رفتار ورود

- نشست فقط با کوکی HttpOnly، SameSite=Strict و Secure روی HTTPS؛ مسیر کوکی `/admin/`، بدون شناسه در URL.
- تعویض شناسه نشست و CSRF هنگام ورود؛ حذف نشست و کوکی هنگام خروج.
- انقضای نشست پس از ۳۰ دقیقه بی‌کاری یا حداکثر ۸ ساعت؛ بررسی فعال‌بودن مدیر در هر درخواست محافظت‌شده.
- تمام POSTهای فعال (ورود و خروج) به CSRF نیاز دارند. GET خروج عملیاتی انجام نمی‌دهد.
- پس از پنج ورود ناموفق در بازه ۱۵ دقیقه‌ای، ورود در همان بازه محدود می‌شود. شمارنده مشترک و تراکنشی است؛ پاک‌کردن کوکی یا تغییر IP آن را دور نمی‌زند. این انتخاب برای تنها یک مدیر عمداً می‌تواند باعث قفل موقت در حمله شود؛ لایه وب‌سرور می‌تواند محدودیت تکمیلی داشته باشد. بعد از پایان بازه امکان تلاش جدید هست.
- خطای نام کاربری و رمز یکسان است؛ داده‌ها و هش رمز در API مدیریتی منتشر نمی‌شوند. صفحات داده‌ها را با HTML escaping نمایش می‌دهند؛ CSP نیز اسکریپت را مسدود می‌کند.
- API مدیریتی فقط‌خواندنی `/admin/api/summary.php` برای کاربر ناشناس JSON با 401 می‌دهد. صفحات ناشناس به ورود هدایت می‌شوند. API عمومی `/api/` عمداً بدون ورود باقی می‌ماند.
- عملیات نوشتن محتوا در فاز سوم فقط پس از احراز هویت، CSRF و اعتبارسنجی انجام می‌شود؛ فهرست مجوزها و سیاست فایل در CONTENT.md است.

## آزمون‌ها

```powershell
node backend/tests/source.test.js
php backend/tests/integration.php
php backend/tests/auth-integration.php
php -d memory_limit=256M backend/tests/content-integration.php
```

تست‌های PHP فقط با `DB_NAME=designestoon_test` اجرا می‌شوند. تست یکپارچه فاز اول به دیتابیس خالی نیاز دارد؛ بعد از آن می‌توان تست احراز هویت را اجرا کرد. تست احراز هویت جدول مدیران و شمارنده تست را خالی می‌کند، یک حساب تصادفی می‌سازد و پس از پایان آن را پاک می‌کند؛ هیچ‌گاه روی داده عملیاتی اجرا نشود. پورت‌های ۱۸۰۸۱ تا ۱۸۰۸۳ آزاد باشند. جزئیات ساخت دیتابیس تست در README آمده است. آزمون احراز هویت شامل ساخت حساب، منع مدیر دوم، ورود/خروج، CSRF، دسترسی غیرمجاز، محدودیت تلاش، نشست منقضی/مدیر غیرفعال، عدم XSS و جلوگیری از ذخیره بدون CSRF است.

## مدیریت محتوا و فاز چهارم

افزودن، ویرایش، بایگانی، دسته‌بندی، تماس و آپلود در فاز سوم پیاده شده‌اند؛ راهنمای کامل در CONTENT.md است. اتصال سایت اصلی به API، تنظیم origin تصاویر و تماس پویا متعلق به فاز چهارم هستند. بازیابی رمز مدیر هنوز رابط ندارد.
